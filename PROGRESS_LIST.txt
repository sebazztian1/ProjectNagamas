RINGKASAN PERUBAHAN V2 & WORKFLOW
- Toko: dbb_luxe (Full Online Jastip & Ready Stock - TIDAK ADA TOKO FISIK).
- Barang dipisah menjadi dua jalur: READY STOCK (/ready) dan JASTIP (/jastip).
- Alur Pemesanan 2 Tahap (ACC Admin Sebelum Transfer):
  1. Customer Checkout (Wajib isi alamat pengiriman) -> Status: Menunggu Persetujuan Admin (pending_approval).
  2. Admin Review & ACC: Admin cek ketersediaan stok ready / slot bagasi koper luar negeri & alamat pengiriman.
     - Jika ACC: Status -> Menunggu Pembayaran (pending_payment). Countdown batas bayar 24 jam baru mulai berjalan di sini.
     - Jika Ditolak: Status -> Ditolak (rejected) beserta alasan penolakan dari admin.
  3. Customer Transfer & Upload Bukti -> Status: Bukti Diupload (payment_uploaded).
  4. Admin Konfirmasi Pembayaran -> Status: Terverifikasi (verified).
  5. Admin Kirim Barang ke Alamat Customer (di luar sistem) -> Status: Selesai (completed).
- Order dipecah menjadi `orders` + `order_items` (multi-item, ada quantity).
- Pembayaran manual: kode unik transfer, batas waktu bayar, riwayat pembayaran.
- Request produk punya alur penawaran (quote) dari admin.
- Notifikasi customer, pengaturan toko, audit log, dan keamanan bukti transfer.
- REVISI V3 & V4 (hasil klarifikasi):
  - dbb_luxe TIDAK MEMILIKI TOKO FISIK (Full Online). Tidak ada opsi ambil mandiri di toko.
  - Seluruh pesanan dikirim oleh Admin langsung ke alamat penerima yang dicatat pada saat checkout.
  - Sistem TIDAK terhubung langsung ke API ekspedisi pihak ketiga / resi otomatis (pengiriman diatur mandiri oleh admin di luar sistem).
  - Live chat bersifat UMUM: satu ruang chat per customer. Produk yang ditanyakan dibagikan sebagai kartu produk di dalam chat.
  - Pendaftaran akun: Username, Nomor WhatsApp, Password, Konfirmasi Password (tanpa email & tanpa OTP).
  - Login memakai: Username ATAU Nomor WhatsApp + Password.
  - Kategori barang hanya terdiri dari 5: Tas, Baju, Sepatu, Aksesoris, dan Lainnya.
  - Kode unik transfer ditiadakan: Total tagihan pembayaran murni subtotal pesanan.

Catatan relasi penting:
- products.trip_id -> jastip_trips.id (hanya untuk product_type = jastip)
- orders.trip_id -> jastip_trips.id; satu order hanya satu tipe (ready ATAU satu
  trip). Keranjang campur dipecah otomatis menjadi dua order saat checkout.
- Harga jastip = (original_price x exchange_rate) + fee, lalu disimpan sebagai
  `price`; order_items menyimpan snapshot harga saat order.
- total_amount = subtotal + shipping_cost (jika ada) + unique_code.
- chat_rooms: satu room per customer (unique customer_id). Produk yang ditanyakan
  dikirim sebagai pesan bertipe `product` (product_id terisi).
- Pengiriman tidak ditangani sistem: tidak ada kolom resi/tracking dan tidak ada
  integrasi ekspedisi. Alamat hanya data order untuk admin.

- dbb_luxe TIDAK MEMILIKI TOKO FISIK (Toko Online Penuh / Jastip Concierge).
- Seluruh barang dikirimkan langsung ke alamat pelanggan melalui jasa pengiriman
  (kurir/ekspedisi) yang diurus langsung oleh admin di luar sistem.
- Sistem tidak menghitung ongkir otomatis, tidak terhubung ke API ekspedisi, dan tidak
  melacak nomor resi secara otomatis. Alamat tujuan dicatat pada saat checkout sebagai
  data panduan admin untuk mengirimkan pesanan (Fase 9.1 & 9.7).
- Bukti transfer bersifat sensitif: simpan di bucket private.
- Simpan file ini sebagai acuan berkala. Ubah `[ ]` menjadi `[X]` setiap kali
  tugas selesai diimplementasikan.
- UX Keranjang Campur (Mixed Cart)
    *Di dokumen tertulis bahwa keranjang campur dipecah menjadi dua order saat checkout.
    *Tips: Saat koding nanti, Anda bisa memilih cara yang paling simpel di UI: jika customer sedang memilih barang jastip dari Trip Jepang, lalu ingin menambah barang dari Ready Stock, beri konfirmasi pop-up modal: "Pesanan Ready Stock dan Jastip akan dibuat menjadi tagihan terpisah ya".
- Auto-Expire Batas Waktu Bayar 24 Jam
    *Jika nanti di-deploy ke platform serverless (seperti Vercel) yang tidak punya server background 24 jam terus-menerus, Anda tidak wajib membuat cron job rumit di awal. Cukup buat pengecekan otomatis saat data dipanggil (lazy expiration): jika payment_deadline < NOW() dan status masih pending_payment, otomatis ubah statusnya menjadi expired.
- Penyimpanan Gambar Bukti Transfer:
    *Keputusan menjadikan bucket receipts/ sebagai Private sangat tepat untuk privasi rekening customer. Gunakan fitur Signed URL (URL dengan masa kedaluwarsa, misal aktif 10 menit) saat admin membuka modal verifikasi bukti transfer.
